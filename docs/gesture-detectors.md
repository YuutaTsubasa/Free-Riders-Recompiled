# 比賽的手勢判斷器

日期：2026-09-27。接續 [用手把進行比賽](race-controls.md)、[實體 Kinect](kinect-sensor.md)。

比賽中遊戲每一格從 Kinect 骨架填出每位玩家的「身體紀錄」（KinnectNuiBox+0x78，4788 bytes，
由 Kinect 管理器更新 `82438930` 填入），再交給約 25 個手勢判斷器。每個判斷器都是
`detect(判斷器, 來源, 結果)`：先向來源要身體紀錄
（`lwz r3,0(r4); lwz r11,0(r3); lwz r10,4(r11); bctrl`），再依紀錄的欄位決定結果，把遊戲
認得的位元寫進結果紀錄（每筆 84 bytes，+4 與 +20 收集位元），回傳 1（認得）、2（相反狀態）
或 0。

手把模式用自己的判斷取代它們（[`nui_race_hooks.cpp`](../src/nui_race_hooks.cpp)）；
實體 Kinect 則交還給遊戲原本的判斷器；webcam 的比賽動作由 [`camera_race_motion.h`](../src/camera_race_motion.h) 另外辨識（見 [攝影機體感輸入](camera-input.md)）。

這就是 [感應器位置](kinect-sensor.md) 會依腳尖判斷胸口方向、必要時對調左右的原因。

## 分析工具

[`scripts/analyse_detectors.py`](../scripts/analyse_detectors.py) 從這台電腦的解碼映像
（`out/recomp/image-loader`，由建置步驟從你的光碟產生）反組譯上表每個判斷器、Kinect
管理器更新與賽前準備，並標出：

- `body+N`：從身體紀錄讀的欄位（追蹤判斷器開頭那個呼叫回傳的暫存器，經過 `mr`、
  `addi` 衍生的指標也算；呼叫其他函式後 r3..r12 視為被改寫）。
- `= 數值`：`lis`/`addi`/`lfs` 指向映像內的常數，直接讀出來，也就是判斷的門檻。
- 呼叫的函式，並附上一層較小的被呼叫函式（關節、向量的輔助函式）。

```
python scripts/analyse_detectors.py out/recomp/image-loader \
    --functions out/recomp/diagnostic/ppc_func_mapping.cpp --output out/detectors.md
```

報告開頭是一張總表（每個判斷器讀的欄位、用到的常數、呼叫），後面是逐一的反組譯。
**報告引用了遊戲的程式碼，只留在自己的電腦上**（`out/` 不進版本控制）。分析是逐行的、
不追蹤分支合流，所以跨分支的常數偶爾會標錯，以總表為線索、反組譯為準。

## 下一步

1. 在有光碟的電腦上產生報告，對照上表，找出每個判斷器讀的身體紀錄欄位與門檻。
2. 再分析 `82438930`：身體紀錄的每個欄位是從哪些關節算出來的。
3. 兩者合起來，就能知道每個手勢需要骨架的哪些關節、動到多少——Kinect 的感應器位置
   換算、webcam 推回的深度，都可以依此驗證與調整。
