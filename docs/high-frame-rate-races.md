# 比賽跑到 60 FPS 以上

日期：2026-11-08。分支 `claude/race-high-fps`。結論：**做得到，建議走「縮短遊戲步長」**
（下面的做法 a），先留在 Test 選項（遊戲分頁的 Race step rate，預設關閉），補完下面的
待辦再考慮變成正式選項。插幀（做法 b）沒有實作，理由在「兩種做法比較」。

測試環境：tailsmachine（i9-14900KF、RTX 4090、143 Hz 螢幕），Windows、Vulkan、
1280×720，全新存檔，Sonic，Rocky Ridge Standard，三圈，12 位車手。沒有用 Tab S12 Ultra。

## 原版怎麼算時間

比賽時鐘（`824B1588`，位址 `83E53810`）本來就支援可變步長：`+40` 是以 60 Hz 為單位的
步長，470 個函式共 817 處讀它。但原版把 `+4` 固定成 1，所以遊戲只在步長剛好 1 時測試過。
`race_frame_clock_hooks.cpp` 已經會改寫這些欄位，做法 a 只是把步長固定成 60/N。

## 步長 0.5 時壞掉的東西：整數計時器

只改步長的第一次試跑就出事：120 Hz 兩場完整比賽裡，每場有 6 到 7 位電腦對手在 Rocky Ridge
的側邊跳台（約 x=-350, z=14）或它前面的斜坡起飛，然後以等速一路往上，到比賽結束都沒掉
下來（y 超過 11000，60 Hz 時最高約 127），玩家因此掛在第 1 名。

原因是遊戲有 19 處把步長截斷成整數，例如跳躍弧線 `822C09A0`：

```
timer -= (int)frames;          // +2292
rise   = timer * timer * k;    // +3140
```

`(int)0.5` 是 0，計時器不走，重力就消失了。這 19 處都是 `fctiwz`／`fctidz`，位址列在
`config/freeriders.toml`（`RaceWholeFramesMidAsmHook`），每個位址都對過執行檔裡的指令。
修法：`RaceWholeFrames` 把步長累加，只回報這一步完成了幾個整幀（120 Hz 時是 0、1、0、1），
由 midasm hook 蓋掉截斷結果。60 Hz 時 hook 不動作。

另外 7 處是 `(int)(frames*k*k2)`，算的是毫秒計時器，截斷只造成很小的誤差，沒有處理。

## 兩種做法比較

| 項目 | a：縮短步長 | b：60 Hz 物理＋插幀 |
| --- | --- | --- |
| 物理與衝量 | 19 處整數計時器要補（已補）；還有約 1～3% 的圈速差 | 不動，比賽與原版完全相同 |
| 動畫 | 跟著步長走，截圖看起來正常，沒有逐格檢查 | 要自己插：骨骼矩陣線性內插，快速旋轉會失真 |
| UI 時間軸 | `for_each_race_ui_step` 已能跑小於 1 的步長，時間顯示每 10 秒走 10.00 秒 | 不動，但 HUD 要分開畫，否則 2D 也會被插 |
| 每次更新加一的計數器 | 風險：遊戲有約 76 處是以「更新次數」累加或遞減（騎手程式範圍內），其中不少只是狀態機，但有些是時間，例如 `+2332` 的停頓；會變快 | 不受影響 |
| Kinect | 遊戲自己的手勢判斷以更新次數算，沒有驗證，Test 選項擋掉 | 不受影響 |
| 輸入延遲 | 一步的時間減半（120 Hz：8.3 ms）；**由步長推算，沒有實測** | 至少多一個物理幀（16.7 ms），因為要等下一幀才能內插；也是推算 |
| CPU | 遊戲邏輯加倍，慢的手機撐不住 | 邏輯不變，但要多錄一次繪製 |
| GPU | 每步畫一格 | 一樣多，所以 GPU 不夠時兩者都救不了 |
| 工程量 | 一個 hook＋19 個位址，已完成 | 要能重播一整格的繪製（含陰影、解析、後製），兩種後端都要 |

做法 b 的可行性有量過：相鄰兩格的繪製有 98.6～99.0% 對得起來（骨骼模型 99.3～99.9%），
但每個繪製的常數都會變（視角矩陣），所以要逐項內插，不能只挑會動的物件。對不起來的
1% 大多是粒子和 HUD，要另外處理。這是可行但很大的工程，而且輸入延遲會變差，對競速遊戲
是反方向，所以沒有做。這個比較的 b 欄沒有實際跑過遊戲，物理欄是「原版就是這樣」，
其他是推算。

## 待辦（變成正式選項之前）

1. 查圈速快 1～3% 的那一段（z=566 到 -100），看是更新次數計數器還是積分誤差。
2. 逐一看以更新次數計時的計數器，尤其是 `+2332` 停頓和 `+0x860`。
3. Forgotten Tomb 對手掉落。
4. 真人遊玩：手感、道具、Grand Prix、Tag、雙人，都沒試過。
5. 手機：撐不住時比賽會變慢（步長固定），要靠步進頻率跟著裝置走；Tab S12 Ultra 等 #176
   那邊做完再測 80 Hz。
6. 線上與體感：目前一律回到 60。

## 開關

- 玩家：啟動器 → Test → 遊戲 → Race step rate（80／90／120／144 Hz）。線上、網路攝影機、
  Kinect，或把跳過畫格關掉時不會套用（`race_step_rate`），game.log 開頭會有
  `RACE_STEP_RATE rate=`。
- 測試：`SFR_RACE_TRACK=<n>` 每 n 步印出所有車手位置，`SFR_RACE_PACING=1` 印呈現間隔，
  `SFR_TEST_RACE_HOLD`、`SFR_TEST_RACE_STEER` 在賽道固定位置按 A 與轉向。Rocky Ridge 在
  選賽道畫面往左一格（`left@11300`）。
