# 用手把進行比賽（進行中）

日期：2026-09-20。分支 `claude/function-boundaries`。接續 [用手把操作選單](pad-menus.md)。

比賽中的操作已經實作，但**還沒有實際跑完一場比賽**：比賽場景的畫面需要離屏算繪目標
（render to texture），原生後端還沒有支援（見最後一節）。目前教學關可以載入、跳過
「On your Gear!」準備動作、進入比賽場景，然後停在該處。

## 手把對應

| 操作 | 按鍵 |
| --- | --- |
| 蹲下蓄力 / 跳躍 | 按住 A／放開 A |
| 踢地加速（Kick Dash） | 按 X 再放開 |
| 煞車、抓取（桿子、軌道） | 按住 B |
| 傾斜轉彎、空中特技旋轉 | 左類比 |
| 切換站姿（Regular／Goofy） | Y |
| 左右招式（Power Skill） | LB／RB |
| 使用道具（按）、搖晃道具（按住）、擦螢幕（按住＋右類比） | RT |
| 舉手 | 右類比上（雙手） |
| 往左／右伸手（拿旁邊的 Ring） | 右類比左／右（推越多伸越遠） |

鍵盤：方向鍵是左類比，Z／空白 A，X B，C X，V Y，Q／E LB／RB，**F RT**，**R LT**，
I／J／K／L 右類比。PS5（DualSense）與 PS4 手把透過 HID 直接讀取（見 `src/sony_gamepad.cpp`）。

**傾斜**（2026-09-21 修正）：遊戲在 `822C6200` 等處比較身體紀錄的 +640 與 +644：
640 較大往右傾 640/644−1，644 較大往左傾 644/640−1，最多 3.5，相等時直立；**+640 為 0
時直接當成傾斜 1.0**。之前只寫 +644（中立 0.5），+640 一直是 0，所以不操作也會右傾。
現在兩個都寫：中立時都是 1，搖桿推到底時一邊是 1+`SFR_RACE_LEAN_SCALE`（預設 1）。

## 做法

比賽中遊戲讀的是每位玩家的「身體狀態」（KinnectNuiBox+0x78 的 4788 位元組紀錄，
原本由骨架資料填入），再交給各種手勢判斷器（vtable 在 821A22xx 一帶，
`detect(判斷器, 來源, 結果)`）。所以：

- **身體狀態**（[nui_race.cpp](../src/nui_race.cpp)）：比賽中（`[83E52F8C]` 非零）
  在 Kinect 管理器每格更新（82438930）之前，把 P1 的紀錄換成我們自己的一份，
  先複製遊戲原本的內容（指標等欄位要保持有效），再寫入手把對應的欄位：
  +8 按住 A、+4／+36 放開 A、+48／+52 X 按下／放開、+72 Y、+88／+32／+644 左右傾斜、
  +40 左類比上下、+16／+96 右類比、+92 RT、+256 LT、+260／+264 LB／RB、+268／+272 B、
  +740／+756 雙手追蹤狀態。離開比賽時把原本的紀錄換回去。
- **手勢判斷器**（[nui_race_hooks.cpp](../src/nui_race_hooks.cpp)）：改寫約 25 個
  判斷器，直接看手把決定結果，並寫入遊戲原本的結果旗標（結果紀錄每筆 84 位元組，
  +4 與 +20 收集旗標），例如跳躍 0x200、蹲下 0x7000、踢地 0x00C00000 → 0x01400000、
  煞車 0x00400100、招式 0x80000／0x100000、站姿 0x200000、特技旋轉 0x800（+56 累積圈數）。
- **賽前準備**：比賽前的「On your Gear!」（狀態在 +2408：0 開始、1 等待、2..6 量測身體、
  7 結束、8 開跑）會要求一連串只有真人身體做得到的姿勢，手把沒有身體可量，
  所以用手把進行時直接跳過 2..6。

## 為了載入比賽而補上的東西

- 原生裝置 Reset（824F4858）：比賽會用自己的後緩衝大小（880 寬）、多重取樣與垂直同步
  重設裝置。原生裝置保留自己的交換鏈，只更新遊戲讀得到的參數。
- 裝置狀態全部解除綁定（824F49C0）與 SetRenderTarget(1..3, NULL)、
  其他參照仍在時的 Device::Release（824F4800）。
- 資源釋放：型別 1..9 且沒有 GPU fence 的資源可以讀取裝置全域（它只在等待 fence 時會用到），
  以及 `MmFreePhysicalMemory`（GPU 或 write-combined 記憶體只忘記、不解除對應）。
- Kinect 深度影像（DepthView）：工作執行緒在主執行緒建立物件之前就會使用它，
  沒有物件時跳過該格。

## 教學關的分段選單

每一段課程結束後會出現環狀選單（Next／Retry／設定…），疊在比賽場景上（所以比賽旗標
仍是開著的）。推進它的是 **A（`ok`）**：選取目前對焦的環狀項目。連續按 A 可以一課一課
跑下去，但盲按會把環轉到「Retry」而重跑同一課，要穩定推進得先用十字鍵把焦點移到
「Next」。

`next` 這個字也送得出去（手把 **X**，比賽中也送，因為這些選單疊在比賽上），但這一頁
不認它——加它是為了其他有 Next 按鈕的頁面。

## 還沒完成

- **離屏算繪目標**：比賽場景會把畫面畫到自己的色彩與深度表面再取用，原生後端目前只有
  一組框架緩衝，`SFR_ALLOW_RENDER_TARGETS=1` 把它們全部別名到同一組，靠每個 pass 之後
  的解析複本串起來。比賽畫面已經完整顯示（見
  [比賽畫面](race-scene-rendering.md) 與 [骨骼調色盤與迴圈常數](shader-vertex-palette.md)），
  但解析複本一律是整個框架緩衝大小、深度解析沒有複製，真正的離屏目標仍然要做。
- 一般比賽（Free Race 等）在**裝備零件畫面**卡住：兩個插槽放滿後，換頁的延遲動作被
  82463808 擋住（它認為零件還在飛向板子）。教學關不經過這個畫面。
- 比賽中的判斷器都還沒有在真正的比賽裡驗證過。
