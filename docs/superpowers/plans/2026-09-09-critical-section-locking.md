# Single-thread critical-section operations plan

> **For agentic workers:** Use subagent-driven-development for the bounded state-transition component, then independent spec and quality review. Root owns import integration and guest-thread validation.

**Goal:** Execute the observed Enter/Leave pair using checked lock state, without fabricating contention or scheduler support.

**Architecture:** Extend critical_section with `void enter_critical_section(GuestMemory&, uint32_t address, uint32_t thread)` and matching `leave_critical_section`. The diagnostic has exactly one executing guest thread. Its identity is the existing guest object at PCR+0x100 (0x70000BB0), whose thread ID at+0x14C is1. Exact Enter82ACB4AC/Leave82ACB4BC import pairs preserve all PPC registers for the void ABI. Reject changed PCR/current-thread identity before mutation. Do not implement TryEnter until observed.

**Representation:** All guest counters and owner use checked BE words. Xenia's native-endian lock_count and Marathon's native owner are host runtime choices, not guest ABI proof. Our supported scalar guest representation is explicitly BE; real-image initial -1/zero counters alone cannot prove positive-counter endian. Preserve header bytes0..15 exactly. Support header type1, signal0 and full28bytes mapped/aligned4. Nonzero spin byte is immaterial without contention and is preserved.

- [x] Extend native critical_section tests first; empty Enter/Leave must fail the first acquisition check. Verify exact BE bytes using non-palindromic owner and positive count. Include interleaved distinct locks.
- [x] Reject with RuntimeStop before writes: null thread, unaligned or incomplete/guarded section, wrong header type/signal, owner0 with inconsistent counts, held state with zero/negative recursion or lock_count != recursion-1, recursive overflow (INT32_MAX), foreign owner (no contention), and leave on free/foreign lock. Validate entire state before any store. Do not increment a waiter count or enqueue a waiter on rejection.
