# Native memory accounting for MmQueryStatistics

Goal: satisfy the real initialization query at82ACC44C using the actual native allocator's state. The original wrapper requests104 bytes and reads total pages, title available pages, title virtual capacity and reserved bytes. No fabricated Xbox allocator statistics.

Design: enforce a default512MiB guest-backing budget in GuestMemory, counting unique host-page-rounded committed extents. Reserves consume virtual address space but not backing budget; overlapping recommit does not double count. Budget overflow stops before host commit or committed-metadata mutation. This is a native runtime policy, not measurement of physical host RAM. Host page size must be a multiple of4096. Expose read-only usage(begin,size) for host-page-aligned ranges, counting clipped reserved/committed backing, and backing_budget(). Constructor allows a smaller aligned test budget. Existing logical access/guards/reservations remain unchanged.

VirtualMemory exposes capacity and actual reserved/committed usage across its two256MiB allocation arenas. MemoryStatistics groups image, stack and static/dynamic TLS mappings into title image/stack/virtual pages; NtAllocateVirtualMemory committed arena pages also count as title virtual pages. Other committed runtime metadata counts as kernel pages. Unimplemented physical/pool/independent heap/page-table/cache categories are zero, as is the absent separate system process section. Available pages = enforced budget minus all committed backing, divided by4096. Highest physical page is the native budget's last page index, not a claimed physical-address mapping. Full104-byte output preflight before any writes; valid size required, null=>C000000D, wrong size=>C0000023; bad memory/guards/read-only/reservation remain explicit stops. Unsupported overlapping category layouts must stop instead of double counting.
