# Native graphics device implementation plan

> Use superpowers:subagent-driven-development for the isolated native owner and its integration review.

Goal: establish the actual Windows renderer device and command queue at the observed Free Riders D3D creation boundary. The original game remains executable and still stops at the unresolved driver import until the complete native D3D adapter replaces that path. This is a dependency of the original title/menu, not its acceptance.

Design: reuse Plume 11926860e878e68626ea99ec88562ce2b8badc4f, the exact Unleashed reference gitlink, with four pinned submodules. Use its D3D12 interface on Windows with the system SDK (Agility option disabled). Root owns dependency/build configuration and diagnostic integration. A small NativeGraphics RAII owner exposes the actual Plume device and direct command queue to subsequent resource/draw adapters. Initialization is explicit and idempotent; access before initialization throws. Prepare the interface/device/queue in locals before committing ownership, and reject null results. No guest device pointer, HRESULT, frame, callback, resource or driver success is fabricated.

Files and work:

- [x] Agent: create src/native_graphics.h/.cpp and tests/native_graphics_test.cpp only. Public API: default constructor/destructor, deleted copy, initialize(), initialized() const noexcept, plume::RenderDevice& device(), plume::RenderCommandQueue& queue(). Forward declare Plume types, use private implementation ownership. Uninitialized access throws std::logic_error; initialization failures throw std::runtime_error. No guest memory or window access.
- [x] Agent: meaningful native test first, then implementation. Verify preinitialization rejection and idempotent device/queue identity. Through the exposed real Plume interfaces, allocate upload/readback buffers, fill a nonuniform byte pattern, record CopyBufferRegion, execute with a real fence, wait and compare all readback bytes. Repeat with a different pattern to catch stale completion; no mock device or CPU memcpy replacing GPU execution. Keep resources alive through completion and check null allocations/maps.
- [x] Root: pin/fetch dependencies, add sfr_native_graphics library and sfr_native_graphics_test Windows targets; link Plume and required Windows GPU libraries. Set a bounded CTest timeout for the GPU test. Add diagnostic initialization at the observed exact824F4CF0/name pair only; log actual adapter name, then continue original function without changing any guest register or memory. Main owns NativeGraphics so lifetime is explicit. No hook installation yet.
- [x] Root: preserve read-only GRAPHICS_ENTRY evidence and add true-entry assertion for actual backend initialization. Build final code, run GPU test and full CTest/Python with real inputs; keep current stop1271/VdInitializeEngines explicit. Verify dependency pins. Spec then quality review, document sources, constraints and evidence; local commit.
