# Bounded native XAM module lookup

Goal: let the real startup acquire a persistent identity for the native XAM service module, then stop honestly at its next unresolved export. No Xbox system binary or completed XAM service implementation is claimed.

Evidence: pinned Xenia `xboxkrnl_modules.cc:86-119` first finds an existing module, increments its load count, writes its handle and returns success. The original game wrapper `sub_824D1E50` calls with flags 9, minimum version 0 and a stack output word. The caller `sub_82A52C60` requests `xam.xex` at 0x82000910 and then export ordinal 2815. The caller entry was verified in the generated source. Marathon's procedure/section lookup hooks are stubs and are not implementation evidence.

Design: a host-owned NativeModules record represents the XAM service namespace. Its opaque guest handle 0x71500000 is mapped only as a guarded word, so unsupported guest structure access stops. Host load count starts at zero and increments on each successful acquisition, bounded at 65535; this is not a guest LDR structure implementation. Only exact `xam.xex`, flags 9 and version 0 are supported for now. All other names/options stop with no output/count mutation. A checked guest C string is limited to 260 bytes including terminator, using 64-bit address arithmetic. Check the complete output word before changing state; source/output aliasing is allowed after capturing the name. Null pointers, unmapped/guarded/read-only output and reservations stop. No procedure address, executable trampoline or synthetic game UI is introduced.
