# Live timestamp bundle and monotonic time base

The diagnostic shares one `GuestClock` between the timestamp bundle, translated `mftb` instructions and `KeQueryPerformanceFrequency`. Its origin is construction in the native process and its source is `std::chrono::steady_clock`. Wall-clock FILETIME queries remain a separate [service](system-time.md).

The profile frequency is49,875,000Hz, matching the pinned Marathon and Unleashed runtime frequency query. `mftb` now returns elapsed monotonic time in these units, and the exact frequency import `0x82ACBAAC` returns49875000 as a64-bit value in r3. No claim is made that raw host CPU cycles have this frequency. Clock scaling, pausing and scheduled timers are not implemented.

Conversion splits elapsed nanoseconds into whole seconds and remainder before multiplication. Both products and their sum fit for every nonnegative int64 input; negative inputs stop with `clock-range`. Uptime divides the same elapsed duration into milliseconds and saturates at UINT32_MAX, following Xenia's bounded uptime result. The tick unit is not a physical resolution guarantee.

`KeTimeStampBundle` is bound only for the verified variable name/address pair `__imp__KeTimeStampBundle` at `0x82000758`. Its guest pointer is `0x71400000`; only the four-byte big-endian uptime field at+16 is exposed. The preceding16 bytes are guarded and offset20 onward is outside the logical mapping. Xenia's pinned [xboxkrnl_module.cc](https://github.com/xenia-project/xenia/blob/95a5c3ee250f80c3b9d139658649d9ffb6db3eec/src/xenia/kernel/xboxkrnl/xboxkrnl_module.cc) initializes a24-byte bundle and updates+16 every millisecond. This diagnostic samples uptime on each scalar read instead of running a host timer that mutates guest memory. Unknown fields are not represented as working zero values.

GuestMemory now supports up to16 aligned, nonoverlapping computed read-only words. Registration requires mapped, unguarded bytes and a nonempty provider. The complete scalar range is checked before providers run. Each overlapping word is sampled once per scalar load and merged into the result in big-endian order, including byte, half-word and unaligned accesses. Backing bytes are not mutated. A read spanning an unknown field or unmapped tail fails before sampling. Raw host pointers do not see computed values; retained generated guest code uses the checked scalar hooks, and raw vector/byte memory bodies remain rejected.

Every checked store rejects an overlap with `memory-readonly` before changing any byte or sampling a provider. Multi-store critical-section operations check the entire object writable first; virtual-memory allocation checks both output words writable before reserving/committing or writing either one. Regression tests reproduced partial state changes without these prechecks and verify unchanged bytes and allocator state with them.

The generator changes only the verified adjacent emission pair `mftb rN` followed by `ctx.rN.u64 = __rdtsc();`, with a matching register0–31. It retains the instruction comment and labels, and emits `sfr::read_time_base()`. Unrecognized forms, mismatched registers, missing reads or remaining raw clock intrinsics cause an `unsupported_time_base` stop. Raw input is preserved. The newly generated `out/recomp/diagnostic-clock` report has20 rewritten read sites; function counts remain46,503 total,29,550 retained and16,953 explicitly stopped.

Tests cover computed reads, single-sample consistency, bounds/guards and write rejection; exact clock conversion and saturation; bundle visibility; multi-store failure atomicity; and strict source transformation. Clock/bundle tests were written first but the initial failure was missing headers, followed by implementation. Deliberately incomplete isolated implementations were subsequently compiled and produced behavioral failures (all4 clock groups,5 of6 bundle groups), then the final code passed. This was additional test sensitivity verification, not a strict behavior-RED-first implementation sequence. Memory, generator and multi-store changes did have behavior RED before their implementation fixes.
