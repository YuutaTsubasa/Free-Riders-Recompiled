# 兩位玩家

在啟動器的 Controls 分配兩位玩家的輸入，或接上第二支手把，再進入遊戲的雙人模式。
第二位玩家也可以使用自己設定的鍵盤按鍵。`SFR_TWO_PLAYERS=0` 會停用第二位玩家。

## 選單與比賽

兩位玩家各自用右類比搖桿舉手、移動游標和操作自己的選單；游標依遊戲當下的玩家身分對應，
不會把骨架位置或畫面左右固定當成玩家編號。雙人選單會讓右手保持向前，無須持續按住 RB。
換頁時會重新準備游標的舉手動作。雙人選單會維持初次舉手，直到遊戲確認游標已啟用，
避免 Gear 等待期間漏掉舉手後必須再按 Back。若選單的延遲動作停住，會在 30 幀後逐幀更新遊戲啟用的兩位玩家；
已經由遊戲原本流程更新的玩家不會重複更新；即使動畫讓延遲動作暫停，仍會記錄游標已更新。雙手把的 Gear 選單中，一方的確認工作尚未完成時，另一方若沒有等待工作，仍會持續更新。
已實機確認 1P 選好 Gear 後，2P 仍可繼續操作，不必按 Back 或等待原本的長時間停頓。
前後選擇目前仍需要右類比向上或向下揮動；操作便利性留待後續改善。

比賽中各自的手把控制各自的身體記錄，沿用 [操作說明](controls.md) 的按鍵。
第二支手把斷線時，第二位玩家的輸入會回到中立，不會改由第一支手把控制，也不會觸發放開 A 的跳躍。
重新連線後可繼續輸入；Loading 期間重新建立玩家物件也會重新讀取目前的身體記錄。
有位移的分割 viewport 使用遊戲 render surface 的邊界，主機的 scissor 仍限制在實際 framebuffer 內。
原點為零的 pass 保留 framebuffer 邊界，配合目前全畫面 resolve／後製的別名實作；明確指定的左半 viewport 與 Loading 尺寸仍照請求保留。

攝影機是第一位玩家的額外輸入，不會把第一支手把改分給第二位玩家。
1P 手把有操作時優先，停止操作 1.5 秒後才回到新鮮的攝影機姿勢；攝影機追蹤
超過 0.5 秒未更新時退回手把。2P 一直使用 Controls 原本指定的手把。
相機的啟動與操作方式見 [攝影機體感輸入](camera-input.md)。

## 裝置與驗證

連著的手把保留自己的玩家編號；新的手把使用可用位置。Controls 的指定裝置、停用位置與按鍵綁定都保留。
Windows 支援 XInput 和 PlayStation HID 輸入，Linux 使用 SDL 的裝置身分。震動目前只有 XInput。

自動化測試可用 `SFR_INPUT_SCRIPT_2` 提供第二位玩家的輸入，語法與 `SFR_INPUT_SCRIPT` 相同。
啟動第二位玩家時 stderr 會印出 `NUI_SECOND_PLAYER present=1`；玩家與 tracking ID 的對應改變時會印出
`NUI_PLAYER_ROUTING`。回歸測試涵蓋游標分工、換頁、斷線、Loading 物件替換、比賽操作及 viewport 尺寸。

實驗版本已實測雙人流程與比賽；整理後的 main 版本另經實機確認 Gear 游標啟用與 1P 確認後的 2P 操作。
